ProtSAE 论文解读：让蛋白语言模型里的特征更像生物概念

一篇关于如何把 SAE 的稀疏特征对齐到蛋白生物概念的论文笔记。

  • Paper Reading
  • Protein Language Model
  • Interpretability
  • SAE

论文：ProtSAE: Disentangling and Interpreting Protein Language Models via Semantically-Guided Sparse Autoencoders
作者：Xiangyu Liu, Haodi Lei, Yi Liu, Yang Liu, Wei Hu
会议：AAAI 2026
图源：本文插图裁自论文原文 PDF，论文采用 CC BY 4.0 许可。

这篇文章想解决的问题很直接：蛋白语言模型已经能在功能预测、结构建模和蛋白设计里发挥作用，但模型内部的表示到底对应了哪些生物学概念，仍然很难讲清楚。

稀疏自编码器，也就是 SAE，近年来常被用来解释大语言模型内部表示。它的想法是把一个高维 hidden state 拆成一组更稀疏的 feature，希望每个 feature 能对应某种可解释概念。把这个思路放到 protein language model 上，就很自然地会问：某个 feature 是否对应 binding pocket、transmembrane segment、protein localization、ion binding site 这类生物概念？

但普通 SAE 有一个关键问题：一个 neuron 往往不是干净地对应一个概念，而是把多个概念混在一起。论文把这个问题称为 semantic entanglement。ProtSAE 的核心贡献，就是尝试在 SAE 训练过程中引入语义监督和蛋白领域知识，让一部分稀疏特征从一开始就朝着指定生物概念对齐。

这篇文章的直觉

普通 SAE 的流程大概是：

  1. 先在 protein language model 的 hidden representation 上训练 SAE。
  2. 训练完以后，再拿带注释的数据集去分析哪些 neuron 和哪些概念相关。
  3. 如果某个 neuron 在含有某个 GO term 的蛋白上经常激活，就说它可能和这个概念相关。

这个流程的问题在于，解释是 post-hoc 的。也就是说，SAE 训练时并不知道我们关心哪些生物概念，它只是在做重构和稀疏化。最后学出来的 feature 可能确实有生物意义，但也可能混合了多个相关或不相关的概念。

ProtSAE 的思路更主动：既然我们已经有 annotation dataset 和 Gene Ontology 这类领域知识，为什么不在训练 SAE 的时候就把它们放进去？

因此，ProtSAE 把 SAE 的 latent activations 分成两类：

  • defined activations：对应预先定义的生物概念。
  • undefined activations：继续保留给模型自己发现未知语义。

这点我觉得是文章里很重要的设计取舍。它不是把所有 feature 都强行解释成已有概念，而是只把一部分 feature 绑定到已知概念，剩下的空间仍然留给模型表达其他信息。

图 1：论文原文 Figure 2。ProtSAE 把 annotation data 和 domain knowledge 放进 SAE 训练过程，而不是训练完以后才做 post-hoc interpretation。

方法一：用 annotation data 引导特征对齐

ProtSAE 在训练时引入一个 concept predictor，用 annotation label 监督 defined activations。直观地说，如果某个蛋白有某个 GO concept，那么对应的 defined neuron 就应该被激活；如果没有，就不应该激活。

但这里有一个技术细节：只用监督信号还不够。因为 SAE 的重构目标可能会更依赖 undefined activations，而把这些语义明确的 defined activations 晾在一边。这样一来，即使某个 defined neuron 会预测概念，它也不一定真正参与重构，更谈不上后续 steering。

为了解决这个问题，ProtSAE 做了两件事。

第一是 feature rescaling。论文让用于重构的权重方向和用于概念预测的权重方向保持一致，但允许它们在幅值上有可学习的缩放。这样语义方向来自监督学习，重构时又能调整强度。

第二是 forced activation。如果模型预测某个概念存在，就强制对应的 defined activation 至少达到一定激活强度，避免它在解码重构时被忽略。这个设计其实挺关键，因为它把“能预测概念”和“真的参与表示”这两件事连了起来。

方法二：把 Gene Ontology 里的逻辑关系放进训练

蛋白概念并不是互相独立的。例如某个更具体的 molecular function 可能是某个更宽泛概念的子类，某些 biological process 之间也可能存在 part-of、regulates 等关系。

ProtSAE 用 ELEmbeddings 把这些本体关系转成几何约束。简单理解，每个概念被表示成嵌入空间里的一个区域，概念之间的 subclass、intersection、existential restriction 等逻辑关系，会变成这些区域之间的包含、相交或平移关系。

文章里用了 NF1 到 NF4 四类 normalized axiom 来建模这些关系。这里我不展开公式，核心是：ProtSAE 不只让 neuron 对齐单个 label，还让这些概念之间的结构关系也进入 SAE 的训练目标。

这一点很适合蛋白任务。因为生物概念天然有层次结构，如果只做 flat label supervision，很容易忽略概念之间的依赖关系。

实验怎么看

论文主要从三个角度验证 ProtSAE。

第一是可解释性可视化。作者展示了 ProtSAE 学到的 feature 可以在蛋白结构上激活到有意义的区域。例如 iron ion binding 相关 feature 会在 TonB-dependent receptor 的相关区域激活，sodium ion transport 相关 feature 会在 transmembrane segment 上更强激活。金属离子结合位点实验里，feature activation 也能高亮出和真实 binding site 对应的位置。

图 2：论文原文 Figure 3。红色强度表示 feature activation，绿色 stick 标出真实 binding site。

第二是 relevance-based 和 probing-based evaluation。作者用来自 UniProtKB/Swiss-Prot 的 77,647 个蛋白构建功能预测数据，概念覆盖 molecular function、biological process 和 cellular component 三个 GO 子本体；另外还用了 Zn2+、Ca2+、Mg2+、Mn2+ 四类金属离子结合位点数据。对比方法包括 Naive SAE、Gated SAE、TopK SAE、SpLiCE 和直接在 PLM hidden representations 上做 linear probe。

结果上，ProtSAE 在 probing-based interpretation 的平均表现里超过其他 SAE baseline 和 SpLiCE，并接近甚至部分超过 linear probe。论文表 1 里，ProtSAE 的 AUPR 为 0.579，AUC 为 0.797；TopK SAE 分别是 0.444 和 0.565；Linear Probe 分别是 0.537 和 0.751。这说明语义引导不只是让解释更好看，也保留了对功能预测有用的信息。

第三是不同稀疏度下的表现。ProtSAE 在不同 sparsity level 下都保持了更好的 AUC，同时 reconstruction fidelity 仍然有竞争力。这个结果很重要，因为 SAE 的常见 trade-off 是：越稀疏越可解释，但重构质量可能下降。ProtSAE 的目标就是让可解释性不要以过多语义损失为代价。

Steering：这篇文章最有意思的部分

除了“解释模型”，作者还做了 intervention，也就是激活特定概念相关的 feature，看看能不能影响 PLM 的生成结果。

他们选择了多个 GO concept，对蛋白序列 mask 50% token，然后比较 intervention 前后的重构序列。评价指标包括 TM-score、RMSD 和 pLDDT。结果显示，intervention 之后 TM-score 提高、RMSD 降低，pLDDT 也有提升，说明生成结果在结构上更接近目标概念相关的自然蛋白。

一个具体 case 是，作者对 “DNA-binding transcription repressor activity” 这个概念做 intervention，生成了一个和自然蛋白 A0A346G484 结构相似的蛋白，TM-score 达到 0.829，RMSD 为 2.75，同时序列一致性只有 30.0%。这个例子想说明：ProtSAE 学到的概念 feature 不只是分类器里的信号，也可能成为控制生成方向的按钮。

图 3：论文原文 Figure 8。蓝色是 intervention 后生成的蛋白结构，黄色是 Foldseek 找到的相似自然蛋白结构。

这部分对 protein design 很有启发。因为如果我们能找到“结构片段/功能概念”在 PLM hidden space 里的可控方向，那么生成模型就不只是 black-box sampler，而可以被更细粒度地引导。

我的理解

我觉得这篇文章最值得关注的是，它把 SAE 从“事后解释工具”推进成了“带先验约束的表示分解工具”。

传统 SAE 的美感在于无监督：我们希望模型自己把 hidden state 拆成可解释 feature。但在蛋白领域，完全无监督未必是最合理的选择。因为我们已经有很多结构化知识，例如 Gene Ontology、binding site annotation、localization annotation。这些知识并不是外部负担，而是很强的 inductive bias。

ProtSAE 的设计实际上是在回答一个问题：可解释性是否应该只来自模型内部，还是可以由模型表示和领域知识共同塑造？

我倾向于后者。尤其是在科学机器学习里，解释性不是为了让 feature 看起来漂亮，而是为了让它能和已有知识体系发生连接。ProtSAE 用 annotation data 和 ontology constraints 让 feature 对齐到概念，再通过 forced activation 让这些 feature 真的参与重构，这个闭环比较完整。

当然，这篇文章也有一些值得继续追问的地方。

第一，ProtSAE 目前主要在 ESM2 上验证，还没有扩展到更多蛋白模型。不同 PLM 的 hidden space 结构可能差异很大，语义引导是否稳定迁移还需要更多实验。

第二，defined concepts 来自已有注释，因此模型更擅长解释已知概念。对未知功能、弱注释蛋白或者 annotation bias 较强的概念，ProtSAE 会如何表现，仍然是开放问题。

第三，steering 的结果很有趣，但离真正可用的蛋白设计还有距离。结构相似性提高并不等价于实验功能成立，后续还需要更严格的 wet-lab 或高质量计算验证。

小结

这篇 ProtSAE 给我的启发是：在蛋白语言模型可解释性里，SAE 不一定只能扮演“显微镜”，也可以变成一种“接口”。它一端连接 PLM 的 hidden representations，另一端连接 GO、binding site、cellular component 这样的生物概念。

如果这个接口足够可靠，我们就能做两件事：一是更清楚地理解模型到底学到了什么，二是更有方向地控制模型生成什么。

对我自己的研究兴趣来说，这类方法也很值得借鉴。无论是蛋白、反应还是分子表示，真正困难的地方往往不是训练一个更大的 encoder，而是把 latent space 里的方向、子空间和科学概念对应起来。ProtSAE 提供了一个很好的例子：把语义监督、本体知识和稀疏表示学习放在一起，可能会让表示学习更接近科学问题本身。
